## 1. 절대 제약 (필수 준수)

### 1-1. 타이포그래피

- **세리프 폰트 전면 금지.** 본문·제목·인용·숫자·로고 어디에도 세리프 계열(슬랩 세리프, 세리프 디스플레이 포함)을 쓰지 않는다.
- **모든 텍스트는 산세리프.** 한글 본문 가독성이 최우선이므로 한글 웨이트가 충분한 산세리프(Pretendard, Noto Sans KR, Wanted Sans 등)를 전제로 스케일을 설계할 것.
- **모노스페이스는 코드 블록·인라인 코드에만 필수.** UI 라벨/메타 정보에 모노를 쓸지는 디자이너 재량이되, 전면적으로 남용하지 말 것.
- 한글은 영문 대비 시각 크기가 크고 대문자 개념이 없다. `letter-spacing`·`text-transform: uppercase`에 의존하는 라벨 체계는 한글에서 깨지므로 주의.

### 1-2. 테마

- **다크 단일 테마.** 라이트 모드와 테마 토글은 제거한다.

### 1-3. 기타

- 반응형 3단 이상 (데스크톱 / 태블릿 / 모바일).
- 접근성: WCAG 2.1 AA 대비비, `:focus-visible` 링 전 인터랙티브 요소, `prefers-reduced-motion` 대응.
- 검색·필터·정렬·페이지네이션은 전부 클라이언트에서 동작 (서버 없음).
- 최종 구현은 Tailwind v4 `@theme` 토큰 기반이므로, 색·간격·타입·radius·shadow·모션을 **토큰 세트로** 제안해 줄 것.

## 4. 페이지별 화면 구성

### 4-1. 홈 `/`

순서대로:

1. **히어로**
   - 사이트 타이틀 / 워드마크 (대형)
   - 한 줄 소개 문구 (블로그가 다루는 주제 3가지를 강조 표시)
   - CTA 2개: 「글 보러가기」(주) · 「소개」(부)

2. **카테고리 카운터 그리드** — 셀 6개
   - 셀 1: Total (전체 글 수, 부가 캡션)
   - 셀 2~6: 카테고리 5종 각각 (카테고리명 + 글 수 + 카테고리 식별 색)
   - 각 셀은 링크: Total → `/blog`, 나머지 → `/blog?category=<id>`
   - ⚠️ **글 수가 0인 카테고리가 다수 존재**(현재 3개). 0 상태 처리 필요

3. **섹션 01 — Featured**
   - 섹션 헤더: 번호 · 짧은 키커 · 섹션 제목 · 우측 보조 링크 슬롯
   - 최신 글 1편의 **대형 피처드 카드** (일반 카드보다 정보량·면적이 큰 별도 변형)

4. **섹션 02 — 최근 글**
   - 섹션 헤더 (우측 슬롯: 최종 갱신일)
   - 포스트 카드 그리드 6개
   - 하단 스트립: 「N개 중 6개 표시」류 카운트 + 전체 글 보기 버튼

5. **섹션 03 — 인용 블록**
   - 짧은 라벨 + 블로그 운영 원칙을 담은 1~2문장 큰 인용구
   - 좌: 라벨/보조 설명, 우: 인용구 형태의 2열 구성

6. **섹션 04 — 태그 인덱스**
   - 섹션 헤더
   - 사용 빈도 상위 16개 태그 칩 (태그명 + 사용 횟수), 클릭 시 태그 필터로 이동
   - ⚠️ **알려진 결함:** 현재 `/blog?tag=` 파라미터는 목록 페이지가 처리하지 않아 필터가 먹지 않는다. 재디자인 시 **태그 필터 UI를 목록 페이지에 포함**시킬지 결정 필요 (권장: 포함)

7. **빈 상태** — 글이 0편일 때 히어로 아래 안내 블록으로 대체

---

### 4-2. 글 목록 `/blog`

1. **헤더 스트립**
   - 브레드크럼 (사이트 / BLOG)
   - 전체 글 수 표시
   - 페이지 타이틀 (대형) + 리드 문단

2. **컨트롤 바 (스크롤 시 상단 고정)**
   - **카테고리 칩 6개**: All + 5개 카테고리. 각 칩에 해당 개수 배지. 선택 상태 필요
   - **검색 입력**: 제목·설명·태그를 대상으로 즉시 필터. 검색 아이콘 + 단축키 힌트 슬롯. **한글 IME 조합 중 처리 필요**
   - **정렬 세그먼트 컨트롤 (3택)**: 최신순 / 긴 글순 / 짧은 글순
   - **뷰 전환 세그먼트 컨트롤 (2택)**: Grid / Index
   - 모바일에서 4개 컨트롤이 어떻게 접히는지 반드시 설계할 것

3. **결과 카운트 행**
   - 「필터 결과 수 / 전체 수」
   - 필터가 걸려 있을 때만 나타나는 **초기화 버튼**

4. **결과 영역 — 2가지 뷰**
   - **Grid 뷰**: 3열 포스트 카드. 카드 구성 = 카테고리 배지 · 날짜 · 커버 이미지(16:9) · 제목 · 설명(2줄 말줄임) · 읽는 시간 + 대표 태그 · 이동 표시
   - **Index 뷰**: 연도별 그룹. 좌측에 연도 + 해당 연도 편수(스크롤 시 고정), 우측에 행 리스트. 행 구성 = 날짜 · 제목 + 설명 · 읽는 시간

5. **페이지네이션** — 페이지당 6편
   - 이전 / 「PAGE nn / NN」 / 다음, 양 끝 비활성 상태
   - ⚠️ **661편 ÷ 6 = 111페이지.** 현재의 이전/다음만 있는 방식은 사실상 탐색 불가.
     재디자인 시 **페이지당 개수 상향 + 페이지 번호 직접 이동 또는 무한 스크롤/더 보기** 중 하나를 제안해 줄 것

6. **목록 끝 마커** — 마지막 페이지 하단 구분 표시

7. **빈 결과 상태** — 상황별 안내 문구(검색어 있음 / 카테고리만 걸림 / 글 자체가 없음) + 필터 초기화 버튼

> 모든 필터 상태는 URL 쿼리에 동기화되고, 기본값은 URL에서 생략된다.

### 4-3. 글 상세 `/blog/[slug]`

위에서부터:

1. **읽기 진행률 바** — 화면 최상단, 스크롤 비율에 비례
2. **목록으로 돌아가기 링크**
3. **메타 스트립** — 카테고리 배지 · 발행일 · 읽는 시간
4. **제목** (페이지 내 최대 타이포)
5. **리드 문단** (요약문)
6. **태그 배지 목록**
7. **커버 이미지** — 16:9, 있을 때만 (실제로는 전편 보유)
8. **광고 슬롯 (상단)** — 환경변수로 켜지는 선택 요소. 자리 확보 필요
9. **본문 영역 — 3열 그리드**
   - 좌: **목차(TOC) 사이드바** — 스크롤 고정
   - 중앙: **본문(prose)**
   - 우: 여백 (그리드 균형용)
   - 태블릿/모바일에서 TOC가 어디로 가는지 설계 필요 (접기/상단 이동/숨김 중 택)
10. **광고 슬롯 (하단)** — 선택
11. **댓글** — GitHub Discussions 기반 임베드(giscus). 외부 iframe이라 스타일 제어가 제한적이며 **다크 테마로 고정**. 감싸는 컨테이너만 디자인
12. **이전 / 다음 글 카드 2개** — 「이전 글」/「다음 글」 라벨 · 제목 · 날짜·읽는 시간. 한쪽이 없을 수 있음

#### 목차(TOC) 상세
- 본문의 h2·h3만 수집. h2에는 자동 번호가 붙음
- 스크롤에 따라 **현재 섹션 활성 표시**
- 클릭 시 부드러운 스크롤 (reduced-motion일 땐 즉시 이동)
- 수집된 heading이 없으면 렌더링하지 않음
- h3는 h2보다 들여쓰기된 계층 표현 필요

#### 본문(prose)에서 스타일이 필요한 요소 전체 목록
- 제목: `h2`(자동 번호 프리픽스 포함) · `h3` · `h4`
- 각 제목 우측에 **hover 시 나타나는 앵커 링크(#)**
- 문단 `p`, 링크 `a`(hover 상태), `strong`, `em`
- 인용문 `blockquote` (내부 문단 포함)
- 인라인 코드 `code`
- 코드 블록 (아래 별도)
- 목록 `ul` / `ol` — 마커 스타일 각각 필요, 중첩 고려
- 구분선 `hr`
- 이미지 `img` (본문 삽입 이미지 — 뉴스 포스트에 Pexels 이미지가 자주 들어감. 캡션/출처 표기 처리 필요)
- 표 `table` / `th` / `td` / 행 hover
- 요소 간 수직 리듬 규칙

#### 코드 블록 (커스텀 컴포넌트)
- 헤더 바: 장식 슬롯 · **파일명** · **언어 라벨** · **복사 버튼**
- 복사 버튼은 `기본` / `복사됨` 2가지 상태
- 본문은 Shiki 신택스 하이라이팅. **하이라이트 테마 팔레트를 새로 지정해 줄 것**
- 라인 하이라이트 등 meta 표기 지원
- 가로 스크롤 처리 필요

#### LinkCard (커스텀 MDX 컴포넌트)
- 외부 링크를 카드로 렌더. 구성: OG 이미지 · 제목 · 설명 · 사이트명 · (선택) 작성자 · 날짜
- **OG 이미지/설명이 없는 경우의 폴백 디자인 필수**

### 4-4. 소개 `/about`

1. **히어로** — 브레드크럼 · 문서 개정 표시 · 대형 타이틀 · 리드 문단
2. **§01 Intro** — 2열
   - 좌: **프로필 카드(스크롤 고정)** — 인물 사진(4:5) · 이름 · 역할 · 메타 5행(위치, 직무, 집필 시작, 대명사, 키보드) · 액션 버튼 2개(Email · GitHub)
   - 우: 자기소개 산문 3문단 (본문 prose 스타일 재사용)
3. **§02 Now** — 섹션 헤더(우측: 최종 갱신일) + **2열 행 리스트 5행**
   - 좌 열: 번호 + 버킷명 + 상태 라벨(색으로 구분되는 3단계)
   - 우 열: 제목 + 설명 문단
   - 하단: 각주 1줄 (외부 링크 포함)
4. **§03 Interests** — 섹션 헤더 + **3열 카드 6개**
   - 카드 구성: 번호 · 주제 라벨(색 구분) · 제목 · 설명 · 참조 태그 배지 2~3개
5. **§04 Stack** — 섹션 헤더(우측: 범례) + **그룹 5개** (Backend / Database / Frontend / DevOps & Infra / Monitoring)
   - 그룹 헤더: 그룹명 + 항목 수
   - 항목 행: 기술명 + 「매일 사용」 표시 + 부가 설명
6. **§05 Selected writing** — 섹션 헤더(우측: 전체 글 링크) + 최근 4편 행 리스트 (날짜 · 카테고리 배지 · 제목 · 읽는 시간)
7. **§06 인용구 + Colophon** — 2열
   - 좌: 대형 인용구
   - 우: **키–값 8행 목록** (프레임워크 / 스타일링 / 콘텐츠 / 하이라이터 / 폰트 / 호스팅 / 라이선스 / 애널리틱스)
8. **§07 Live stats** — 섹션 헤더 + **외부 애널리틱스 대시보드 iframe** + 출처 캡션
   - 외부 임베드라 내부 스타일 제어 불가. 컨테이너와 반응형 높이만 설계
9. **§08 Elsewhere** — 섹션 헤더 + 링크 카드 2개(라벨 · 핸들 · 설명 · 외부 이동 표시) + 하단 이메일 CTA 블록(라벨 + 대형 이메일 주소 + 전체 글 보기 버튼)

> ⚠️ 현재 섹션 번호가 §07 다음에 §06이 오도록 어긋나 있다. 재디자인 시 번호 체계를 다시 정리할 것.

### 4-5. 404

1. **상태 바** — 에러 라벨(색 구분) · 라우트 상태 · 상태 코드 / 우측: 빌드 식별자
2. **2열 히어로**
   - 좌: 초대형 `404` 숫자 + HTTP 상태 라벨
   - 우: 제목 · 안내 리드 · **요청한 경로 표시** · CTA 2개(홈으로 / 전체 글 보기)
3. **추천 글 3편** — 구분선 + 라벨 + 전체 글 링크 + 카드 3개

> 기존 404 배경 장식(코드 로그가 비처럼 깔리는 연출)은 제거한다.

| 프로필 카드 | About 전용 |

## 7. 재디자인에서 함께 해결하고 싶은 문제

1. **661편 규모의 탐색성** — 6편/페이지 · 이전/다음만으로는 과거 글에 도달할 수 없다.
2. **태그 필터 미동작** — 홈의 태그 칩이 실제 필터로 이어지지 않는다.
3. **카테고리 편중** — news가 99%다. 카테고리 UI가 이 편중을 견디는 형태여야 한다.
4. **빈 카테고리 표시** — 0편 카테고리 3개의 표현.
5. **정보 밀도** — 라벨·번호·메타 표기가 화면당 지나치게 많지 않도록. 깔끔하고 절제된 방향을 원한다.

## 8. 원하는 산출물

1. **디자인 토큰 세트** — 색(다크 단일) · 타입 스케일 · 간격 · radius · shadow · 모션. Tailwind v4 `@theme` 형태로 바로 옮길 수 있게.
2. **컴포넌트 스펙** — §5 인벤토리 전체, 상태 포함.
3. **페이지 레이아웃** — 5개 화면(홈 · 목록 · 상세 · 소개 · 404) × 데스크톱/태블릿/모바일.
4. **본문(prose) 타이포그래피 스펙** — §4-3의 요소 목록 전체 + 코드 하이라이팅 팔레트.
