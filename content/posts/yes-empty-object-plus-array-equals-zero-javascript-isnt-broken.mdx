## 개요

자바스크립트에서 빈 객체에 빈 배열을 더하면 0이 나옵니다. 정확히는 특정 조건에서만 그렇습니다.

```javascript
{} + [] // 0
```

개발자 Sylwia Laskowska가 한동안 쉬었던 'JS WTF' 시리즈를 다시 시작하면서 첫 소재로 이 코드를 골랐습니다. 독일 뮌헨에서 열린 iJS 컨퍼런스를 마치고 돌아오는 길에 프랑크푸르트 공항에서 두 시간이 남아 쓴 글이라고 합니다. 결론부터 말하면 이건 버그가 아닙니다. 파서가 코드를 해석하는 규칙과 타입 강제 변환(type coercion)이 맞물린 결과입니다.

## 왜 이상한 동작이 사라지지 않을까

자바스크립트는 1990년대 중반 브라우저 전쟁 한가운데서 단 10일 만에 만들어졌습니다. 그 뒤로 수많은 변화를 거쳐 지금은 당시와 비교하기 어려울 만큼 기능이 늘었습니다.

문제는 하위 호환성입니다. 지금도 옛날 방식의 자바스크립트에 기대어 돌아가는 웹사이트가 수백만 개 있고, 언어를 바꿀 때마다 이 사이트들을 고려해야 합니다. 저자는 그래서 자바스크립트의 기묘한 동작이 아마 영원히 남을 거라고 말합니다.

## `{}`는 객체가 아닐 수도 있다

먼저 알아둘 점이 있습니다. 이 상황에서 자바스크립트는 `{}`를 객체로 보지 않을 수 있습니다.

일반 스크립트에서 문장 맨 앞에 아래 코드가 오면,

```javascript
{} + []
```

파서는 이것을 두 개의 별개 코드로 읽습니다.

```javascript
{}    // 비어 있는 코드 블록
+[]   // 빈 배열에 단항 플러스 연산자 적용
```

앞의 `{}`는 객체 리터럴이 아니라 아무 일도 하지 않는 빈 블록입니다. 진짜 계산은 뒤쪽 `+[]`에서 일어납니다.

## `+[]`가 0이 되기까지

자바스크립트는 동적 타입이면서 약한 타입(weakly typed) 언어입니다. 변수에 숫자를 넣었다가 문자열로 바꿔도 아무 말을 하지 않고, 필요하면 알아서 타입을 바꿔버립니다. 이 암묵적 변환이 가끔 꽤 '창의적인' 결과를 냅니다.

두 값을 더하거나 문자열을 잇는 이항 `+`와 달리, 단항 `+`는 피연산자를 숫자로 바꾸려고 합니다. 그래서 `+[]`는 사실상 아래 코드와 같습니다.

```javascript
Number([])
```

배열을 숫자로 바꾸기 전에 한 단계가 더 필요합니다. 배열은 객체이므로 먼저 원시값(primitive)을 얻어야 하는데, 평범한 빈 배열이라면 이 과정에서 결국 `toString()`이 호출됩니다.

```javascript
[].toString(); // ""
```

빈 배열은 빈 문자열이 됩니다. 전체 흐름을 정리하면 이렇습니다.

```javascript
Number([]);

// 배열이 먼저 원시값인 문자열로 바뀐다
Number("");

// 빈 문자열은 숫자 0이 된다
0
```

결국 `{} + []`는 "아무것도 안 하는 블록" 뒤에 `+[]`가 붙은 꼴이 되고, 그 값이 0입니다.

```javascript
{}  // 아무 일도 하지 않음

+[] // 0
```

저자는 이 코드가 이렇게 멀쩡해 보이는 결과를 내는 언어를 달리 떠올리지 못하겠다고 했습니다. PHP였다면 아마 치명적 오류(fatal error)를 냈을 거라면서, PHP도 나름의 놀라운 동작이 많으니 너무 심하게 탓하진 말자고 덧붙였습니다.

## 맥락이 바뀌면 결과도 바뀐다

중요한 점은 이 동작이 코드를 어떻게 파싱하느냐에 달려 있다는 것입니다.

```javascript
// 일반 스크립트에서 독립된 문장일 때
{} + [] // 0

// 괄호로 감싸 {}를 객체로 해석하게 만들면
({} + []) // "[object Object]"

// 함수 인자 안에 넣었을 때
console.log({} + []); // "[object Object]"
```

괄호 안이나 함수 인자 자리에서는 `{}`가 객체로 해석되므로 결과가 완전히 달라집니다.

## `[] + []`와 `[] + {}`는?

원리를 알고 나면 나머지 예제도 쉽게 풀립니다.

```javascript
[] + [] // ""
```

여기서는 이항 `+`가 쓰입니다. 두 배열이 모두 빈 문자열로 바뀌고, 빈 문자열 두 개를 이으면 빈 문자열입니다.

순서를 뒤집으면 어떨까요?

```javascript
[] + {} // "[object Object]"
```

`{} + []`는 0이었는데 순서를 바꾸니 전혀 다른 값이 나옵니다. 저자는 자바스크립트에서는 덧셈의 교환법칙도 선택 사항인 모양이라고 농담합니다. 물론 엄밀히 따지면 여기서 하는 일은 수학적 덧셈이 아니고, 파서도 두 식을 다르게 다룹니다.

실제 동작은 이렇습니다. 빈 배열은 빈 문자열이 되고, 일반 객체는 고유한 문자열 표현을 갖습니다.

```javascript
[].toString()       // ""
({}).toString()     // "[object Object]"
```

그래서 자바스크립트는 사실상 아래 연산을 수행합니다.

```javascript
"" + "[object Object]" // "[object Object]"
```

저자는 폴란드 속담 'proste jak budowa cepa(도리깨 만들기만큼 간단하다)'를 인용하며, 터무니없이 쉽다는 뜻의 이 말이 자바스크립트에 딱 맞는다고 했습니다.

## 정리

글에 나온 예제는 하나도 버그가 아닙니다. 모두 자바스크립트의 파싱 규칙, 타입 강제 변환, 그리고 오랜 하위 호환성의 역사가 만든 결과입니다. 누군가 `{} + []`가 0이라서 자바스크립트가 고장 났다고 말하면, 왜 그렇게 되는지 설명해줄 수 있습니다.

저자는 다음 편에서 `{} + {}`가 왜 `NaN`이 되는지 다루겠다고 예고했습니다.
