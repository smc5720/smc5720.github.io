## 개요

요즘 AI 코딩 벤치마크는 대부분 웹 앱이나 CRUD 대시보드를 만들게 합니다. 최신 모델은 이런 과제를 한 번에 끝내기 때문에 점수 차이가 잘 드러나지 않습니다. 그래서 Jhin Lee는 Antigravity 안에서 돌아가는 **Gemini 4 Argon**에 훨씬 까다로운 과제를 냈습니다. **Flutter로 60 FPS 마리오 카트풍 3D 레이싱 게임을 만드는 것**입니다.

조건이 하나 더 있었습니다. **외부 에셋은 하나도 쓰지 않는다.** Blender로 만든 `.glb` 모델도, `.png` 텍스처도, 내려받은 `.mp3` 효과음도 금지입니다. 화면에 보이고 귀에 들리는 건 전부 코드로 만들어야 했습니다.

![Flutter Kart Grand Prix Gameplay](https://raw.githubusercontent.com/leehack/flutter-kart-gp/main/docs/preview.gif)

- **브라우저에서 플레이 (WebAssembly):** [leehack.github.io/flutter-kart-gp](https://leehack.github.io/flutter-kart-gp/)
- **소스 코드 (MIT):** [github.com/leehack/flutter-kart-gp](https://github.com/leehack/flutter-kart-gp)

## 본문

### 결과부터: 프롬프트 15번, 3시간 26분

빈 폴더에서 시작해 GitHub Pages에 WebAssembly 게임을 올리기까지 **프롬프트 15번**, 실제 작업 시간 약 **3.5시간**이 들었습니다.

| 항목 | 결과 |
| :--- | :--- |
| **테스트 모델** | **Gemini 4 Argon** |
| **전체 프롬프트 수** | **15** |
| **실제 작업 시간** | **3시간 26분** (플레이 테스트 포함 전체 4시간 35분) |
| **외부 3D·이미지 파일** | **0개** (전부 코드로 생성) |
| **크로스 플랫폼 코드 공유율** | macOS 데스크톱과 WebAssembly 간 **96.7%** |

작성자는 긴 기술 명세 대신 팀원과 플레이 테스트하듯 짧은 피드백만 줬습니다. 15번의 프롬프트는 크게 네 단계로 나뉩니다.

- **1~4번 (게임 뼈대):** "Flutter로 3D 카트 레이싱 게임 만들어줘", "비주얼 다듬어줘", "Llama랑 Flutter Dash 넣어줘", "마리오 카트랑 비교해서 개선해줘". 이 단계에서 트랙, 플레이 가능한 마스코트 4종, 3단계 드리프트 부스트, 점프대, 코인, 아이템 7종이 생겼습니다.
- **5~9번 (화면 보며 디버깅):** 에이전트가 직접 macOS 앱을 띄우고 자기 창을 스크린샷으로 찍은 뒤 카메라 각도, 캐릭터 실루엣, 벽 충돌을 고쳤습니다.
- **10~12번 (오디오와 속도):** "BGM이 너무 싸구려 같아", "게임이 좀 너무 빨라", "BGM 루프가 끊겨" 같은 불만을 전달했습니다.
- **13~15번 (WebAssembly 배포):** "이거 웹에서도 돌아가?"라고 묻고 GitHub Pages에 WebAssembly 빌드를 배포하게 했습니다.

### Blender 없이 3D 캐릭터 만들기

AI는 Blender를 열어 마우스로 메시를 조각할 수 없습니다. 그렇다면 **Flutter Dash**, **Turbo Llama**, **Bugdroid**, **Blaze Dino**는 어떻게 만들었을까요?

Gemini 4 Argon은 3D 모델링을 **레고 조립**처럼 다뤘습니다. [`flutter_scene`](https://pub.dev/packages/flutter_scene)과 **Flutter GPU**를 쓰고, [`kart_builder.dart`](https://github.com/leehack/flutter-kart-gp/blob/main/lib/game/kart_builder.dart)에서 구·원뿔·캡슐·링·박스 같은 기본 도형을 조합해 캐릭터와 카트를 하나씩 만들었습니다.

![Procedural 3D Pipeline](https://raw.githubusercontent.com/leehack/flutter-kart-gp/main/docs/article/procedural_pipeline_diagram.jpg)

텍스처도 같은 방식입니다. `.png` 파일이 없으니 [`pbr_assets.dart`](https://github.com/leehack/flutter-kart-gp/blob/main/lib/game/pbr_assets.dart)에서 게임이 켜질 때 아스팔트 질감, 타이어 스키드 마크, 노면 범프 맵을 메모리에서 직접 생성합니다.

작성자가 가장 인상 깊었다고 꼽은 장면은 **모델이 화면을 보고 스스로 고친 순간**입니다. 처음 만든 Flutter Dash는 캐릭터 선택 화면에서 정면으로 보면 귀여웠습니다. 그런데 레이스가 시작되면 플레이어는 운전자의 뒤통수만 보게 되고, 그 각도에서 Dash는 그냥 파란 볼링공처럼 보였습니다.

Gemini 4 Argon은 실행 중인 게임 창을 스크린샷으로 찍어 보고 이 문제를 알아챘습니다. 그리고 코드로 돌아가 고글 끈, 펄럭이는 빨간 스카프, 꼬리 깃털, 비스듬한 날개를 붙였습니다. 덕분에 뒤에서 봐도 한눈에 Dash라는 걸 알아볼 수 있게 됐습니다.

### "소리가 너무 싸구려 같아"

5번째 프롬프트에서 음악과 효과음을 요청하자, 모델은 외부 파일을 쓰지 않으려고 사인파와 사각파로 Dart 신시사이저를 직접 짰습니다. 돌아가긴 했지만 소리는 싸구려 8비트 장난감 같았습니다. 그래서 10번째 프롬프트에서 이렇게 말했습니다.

> *"BGM이랑 효과음 좀 더 개선해줄 수 있어? 너무 싸구려 같아..."*

작성자는 신스 계산식을 조금 손보는 정도를 예상했습니다. 그런데 모델은 다른 길을 찾았습니다. **모든 Mac에는 macOS 안에 Roland MIDI 악기 라이브러리 전체가 숨어 있다**는 사실을 떠올린 것입니다. 위치는 `/System/Library/Components/CoreAudio.component/Contents/Resources/gs_instruments.dls`입니다.

모델은 Swift 스크립트 [`generate_studio_audio.swift`](https://github.com/leehack/flutter-kart-gp/blob/main/tool/generate_studio_audio.swift)를 작성했습니다. 이 스크립트는 Apple 내장 사운드뱅크를 불러와 브라스, 슬랩 베이스, 재즈 오르간, 드럼을 멀티트랙으로 연주하고, 스튜디오 리버브를 걸어 스테레오 WAV 파일로 내보냅니다.

#### 루프가 끊기는 문제

새 음악은 훌륭했지만, 14초마다 루프가 처음으로 돌아갈 때 아주 짧게 끊기는 소리가 났습니다.

![Seamless 3-Cycle Audio Looping](https://raw.githubusercontent.com/leehack/flutter-kart-gp/main/docs/article/audio_loop_diagram.jpg)

원인은 리버브였습니다. `0:00` 시점에는 리버브 공간이 완전히 조용하지만, `0:14` 시점에는 마지막 음의 잔향이 아직 울리고 있습니다. 두 지점을 이어 붙이면 잔향이 뚝 끊깁니다.

모델은 8마디 루프를 **세 번 연달아** 렌더링한 뒤 **가운데 테이크(Take 2)** 만 잘라냈습니다. Take 2 앞부분에는 Take 1에서 넘어온 자연스러운 잔향이 이미 깔려 있기 때문에, 이걸 반복 재생하면 끊김 없이 무한히 이어집니다.

### 왜 Flutter였나: macOS 네이티브에서 WebAssembly까지 7분

작성자가 이 실험에 Flutter를 고른 큰 이유는 **크로스 플랫폼 3D**를 시험해 보고 싶어서였습니다.

이 게임은 무거운 서드파티 게임 엔진을 쓰지 않습니다. 물리 연산은 Flutter 표준 60 Hz `Ticker`, 3D 렌더링은 `flutter_scene`, 속도계·미니맵·아이템 룰렛 같은 2D HUD는 일반 Flutter `CustomPainter` 오버레이가 맡습니다.

![Flutter Kart Grand Prix Architecture](https://raw.githubusercontent.com/leehack/flutter-kart-gp/main/docs/article/architecture_diagram.jpg)

12번째 프롬프트까지는 Apple Metal 위에서 도는 **macOS 네이티브 데스크톱 앱**으로만 실행했습니다. 그리고 13번째 프롬프트에서 물었습니다.

> *"이거 웹에서도 돌아가?"*

Dart 코드 **12,082줄** 중 **96.7%** 가 **수정 없이** 웹에서 돌아갔습니다. 3D 카트, 셰이더, 텍스처, 물리, HUD 모두 그대로 **WebAssembly(`flutter build web --wasm`)** 로 컴파일됐습니다.

바꿔야 했던 건 오디오 플레이어뿐이었습니다. macOS는 커맨드라인 오디오를, 브라우저는 HTML5 오디오를 써야 하기 때문입니다. [`sound_backend.dart`](https://github.com/leehack/flutter-kart-gp/blob/main/lib/game/sound_backend.dart)에 조건부 import 세 줄을 넣는 것으로 해결했습니다.

```dart
export 'sound_backend_stub.dart'
    if (dart.library.io) 'sound_backend_io.dart'
    if (dart.library.js_interop) 'sound_backend_web.dart';
```

macOS 네이티브 3D 게임을 Chrome에서 돌리기까지 걸린 시간은 **7분이 채 안 됐습니다**.

#### GitHub Pages에 숨어 있던 버그

WebAssembly 빌드를 GitHub Pages에 올리자 사이트가 로딩 스피너에서 멈췄습니다. 작성자가 에이전트에게 한 말은 "정적 웹이 안 돌아가는 것 같아"가 전부였습니다.

에이전트는 헤드리스 Chrome으로 실제 URL을 열어 네트워크 로그를 확인했고, 3D `.shaderbundle` 파일들이 `404 Not Found`를 반환한다는 사실을 찾아냈습니다.

원인은 꽤 교묘했습니다. `flutter_scene`은 로컬에서 셰이더를 컴파일할 때 빌드 산출물이 커밋되지 않도록 생성 폴더에 `*` 한 줄짜리 `.gitignore`를 넣어 둡니다. 그런데 `flutter build web`이 에셋을 `build/web`으로 복사할 때 **이 `.gitignore`까지 같이 복사합니다**. 그래서 `build/web`을 `gh-pages` 브랜치에 푸시하자 Git이 3D 셰이더를 전부 무시해 버렸습니다.

배포 전에 하위 폴더의 `.gitignore`를 지우자 바로 해결됐습니다.

```bash
flutter build web --release --wasm --base-href "/flutter-kart-gp/"
find build/web -name ".gitignore" -delete
```

### 사람이 개입해야 했던 지점

한 번에 끝나는 마법은 아니었습니다. 작성자는 모델이 첫 시도에서 어디서 막혔는지 지켜본 것이 이번 테스트에서 가장 흥미로웠다고 말합니다.

1. **카메라 시점을 못 봤다:** 코드로 3D 모델을 만들 때 처음엔 캐릭터를 정면 기준으로 디자인했습니다. 실제 플레이 스크린샷을 보기 전까지는 플레이 시간의 95%를 카트 뒷모습만 보게 된다는 걸 몰랐습니다.
2. **오디오는 '이 정도면 됐다'에서 멈췄다:** 혼자 두면 기본 8비트 비프음 오실레이터로 끝냈습니다. 사람이 "너무 싸구려 같아"라고 밀어붙인 뒤에야 macOS 내장 Roland 악기 뱅크를 찾아냈습니다.
3. **속도를 사람이 아니라 AI 기준으로 맞췄다:** 첫 버전은 적정 속도보다 약 22% 빨랐습니다. AI 드라이버는 반응 지연이 없기 때문입니다. 사람이 코너를 돌 수 있도록 카트 속도를 낮춰 달라고 따로 요청해야 했습니다.

### 작성자의 평가

작성자가 가장 감탄한 부분은 Gemini 4 Argon이 Dart와 Swift 코드 13,000줄을 썼다는 사실이 아니었습니다. **지적을 받고 나서 어떻게 만회하는지**였습니다.

3D 에셋 파일을 쓸 수 없자 코드로 레고식 리그를 조립했습니다. 첫 신스 소리가 싸구려 같다는 말을 듣고는 macOS 안에 숨어 있던 시스템 MIDI 사운드뱅크를 찾아냈습니다. GitHub Pages에서 WebAssembly 빌드가 깨졌을 때는 실제 브라우저 로그를 뒤져 셰이더를 집어삼킨 숨은 `.gitignore`를 잡아냈습니다.

### 직접 해 보기

WebAssembly 빌드는 Chrome, Edge, Brave 브라우저에서 바로 플레이할 수 있습니다. 저장소를 클론해 macOS에서 네이티브로 실행해도 됩니다.

- **브라우저에서 플레이 (Wasm):** [https://leehack.github.io/flutter-kart-gp/](https://leehack.github.io/flutter-kart-gp/)
- **GitHub 저장소:** [https://github.com/leehack/flutter-kart-gp](https://github.com/leehack/flutter-kart-gp)

```bash
git clone https://github.com/leehack/flutter-kart-gp.git
cd flutter-kart-gp
flutter config --enable-flutter-gpu
flutter run -d macos   # or: flutter run -d chrome
```
