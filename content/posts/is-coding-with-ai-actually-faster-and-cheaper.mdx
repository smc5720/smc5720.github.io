## 개요

AI 코딩 에이전트가 개발자를 얼마나 빠르게 만들어 줬을까요? 개발자 Sylwia Laskowska는 베를린에서 열리는 AI Coding Summit 패널 토론을 준비하면서 "내 생각엔 그렇다"는 감 말고 실제 연구 결과를 모아 봤습니다.

결론부터 말하면 코드를 쓰는 속도는 분명히 빨라졌습니다. 하지만 그만큼 소프트웨어가 더 많이 출시되지는 않았습니다. 50만 명 넘는 GitHub 개발자 데이터를 분석한 연구에서 커밋은 240% 늘었는데 릴리스는 30% 느는 데 그쳤습니다. 비용 쪽에서는 의외의 결과가 나왔습니다. 토큰 가격보다 에이전트가 얼마나 일을 잘하느냐가 전체 비용을 더 크게 좌우한다는 것입니다.

## 본문

### 커밋은 폭증했는데, 출시는 그만큼 늘지 않았다

저자의 체감은 이랬습니다. 코드는 확실히 빨리 쓰는데, 개발 프로세스 전체가 눈에 띄게 빨라지지는 않았다는 것입니다. 코드 리뷰, 분석, 논의 같은 단계는 그대로 남아 있으니까요. 조금 빨라지고 스트레스가 조금 줄어든 정도라고 했습니다.

MIT와 와튼스쿨 경제학자들이 2026년 9월 개정한 연구도 이 감각과 비슷한 결과를 냈습니다. 연구진은 50만 명 넘는 GitHub 개발자 데이터를 분석해 자율 코딩 에이전트 도입 이후의 누적 변화를 추정했습니다.

| 지표 | 추정 변화 |
| --- | --- |
| 코딩 활동량(커밋) | **+240%** |
| 소프트웨어 릴리스 | **+30%** |
| 조사 대상 마켓플레이스 전체 앱 사용량 | **전체적인 증가 없음** |

관찰 데이터로 낸 추정치이긴 하지만, 커밋 증가폭과 릴리스 증가폭의 차이는 꽤 큽니다. 저자는 신규 프로젝트라면 사정이 다를 수 있다고 봤습니다. 다만 자신이 맡고 있는 대규모 레거시 시스템에서는 10배 개선 같은 변화를 본 적이 없다고 했습니다. 최근 AI 보안 이슈가 잇따르면서 오히려 일이 더 복잡해졌다는 느낌도 덧붙였습니다.

### 개인 개발자의 속도: 연구마다 결과가 다르다

그렇다면 개발자 한 명 한 명은 빨라졌을까요? 데이터는 엇갈립니다.

| 연구 | 결과 | 측정 대상 |
| --- | --- | --- |
| Cui 외, *Management Science*, 2026 | **+26.08%** | 완료한 작업 수 |
| METR, 2025년 7월 | **19% 느려짐** | 작업 완료 시간 |
| *Science*, 2026년 1월 | **+3.6%** | GitHub 분기별 코딩 활동량 추정 증가율 |
| Borg 외, 2026년 6월 | **30.7% 단축** | 관찰 단계에서 구현 시간 감소폭(중앙값) |

연구마다 대상 개발자와 도구, 작업이 다르고 퍼센트가 뜻하는 것도 제각각입니다. 그래도 여러 연구가 생산성 향상을 가리키고 있습니다. 모두가 갑자기 10배 개발자가 된 건 아니지만 개선은 실제로 있다는 뜻입니다.

### "더 빨라졌다"는 착각: METR 실험

혼자 다른 결과를 낸 연구가 METR입니다. 2025년 연구라 요즘 AI 업계 기준으로는 오래된 자료지만, 저자는 이 연구의 한 대목을 특히 흥미롭게 봤습니다.

실험 전에 개발자들은 AI 덕분에 약 **24% 빨라질 것**이라고 예상했습니다. 실제로는 **19% 느려졌습니다.** 그런데 실험이 끝난 뒤에도 참가자들은 여전히 AI가 자기를 더 빠르게 해 줬다고 믿었습니다. 직접 측정하기 전까지 사람이 자기 자신을 얼마나 쉽게 속이는지 보여 주는 사례입니다.

METR은 2026년 2월 후속 업데이트를 냈습니다. 연구진은 최신 도구가 더 도움이 될 가능성이 크다고 보면서도, 참여 의사를 밝힌 개발자 구성의 편향 때문에 속도 향상폭을 신뢰성 있게 추정하지는 못했다고 밝혔습니다.

### 개발 비용은 정말 줄었을까

저자는 개발 비용이 줄었느냐는 질문에 "아직은 아니다"라고 답하겠다고 했습니다.

2025년 DORA 연구와 2026년 3월에 나온 후속 자료가 많은 개발자가 이미 느끼던 점을 짚었습니다. 코드 작성에서 아낀 시간 상당 부분이 그 코드를 감사하고 검증하는 데 들어간다는 것입니다. 그래서 구현 단계에서 아낀 비용이 프로덕션에 이를 즈음에는 줄어들 수 있습니다. DORA는 업무 부담이 어디로 옮겨 가는지는 설명했지만 전체 비용이 줄었는지에 대해서는 결론을 내리지 않았습니다.

한 에이전트가 코드를 쓰고, 다른 에이전트가 리뷰하고, 또 다른 에이전트가 테스트해서 그대로 배포하는 멀티 에이전트 팀 이야기도 있습니다. 저자는 이런 방식이 통하는 상황도 있겠지만, 금융 소프트웨어처럼 미션 크리티컬한 시스템에서는 매우 조심해야 한다고 말했습니다.

### 토큰 비용: 싼 모델이 오히려 비쌀 수 있다

코드를 빨리 써서 아낀 돈을 결국 토큰 비용으로 다 쓰는 건 아닐까요? 저자도 가장 비싼 모델을 아무 데나 쓴다면 그럴 거라고 짐작했습니다. 그런데 연구 결과는 예상과 달랐습니다.

AI 보조 개발의 경제성을 다룬 최근 연구 두 편이 있습니다. 2026년 9월 Potluri 연구팀이 낸 연구와 2026년 10월 Steffen Herbold가 낸 연구입니다. 두 연구 모두 **토큰 가격보다 에이전트의 실제 성능이 더 중요할 수 있다**는 결론을 냈습니다.

- **Potluri 연구:** 작업을 더 많이 해결한 모델은 상당한 비용 절감 효과를 냈습니다. 반면 성능이 낮은 모델은 여러 작업 유형에서 오히려 비용이 더 들었습니다. 싼 모델이라도 계속 실패해서 다시 돌려야 하면 금방 비싸집니다.
- **Herbold 연구:** 개발자와 AI 에이전트가 섞인 팀을 가정해 432개 시나리오를 시뮬레이션했습니다. 급여, 토큰 비용, 감독 비용, 버그, 기술 부채까지 넣었습니다. 성능이 높은 에이전트를 쓴 팀은 대체로 AI 없이 일하는 개발자 팀보다 비용이 적게 들었고, 성능이 낮은 에이전트의 결과는 엇갈렸습니다. 결과물이 좋을수록 검토하고 고치는 비용이 줄어들기 때문에 **토큰 가격보다 에이전트 성능이 더 중요했습니다.**

단, Herbold의 결과는 시뮬레이션이고 Potluri의 추정은 벤치마크와 경제 모델링에서 나왔습니다. 절감액이 토큰 비용을 넘어서는 조건을 두 가지 방식으로 추정한 것일 뿐입니다. 상용 소프트웨어를 실제로 만들고 유지하는 데 드는 비용은 훨씬 큰 문제입니다.

### 정리: 아직 판단하기엔 이르다

여러 연구를 종합하면 AI는 코딩을 더 빠르고 저렴하게 만들 수 있습니다. 특정 작업에서는 생산성이 올랐다는 결과가 여러 번 나왔고, 경제 모델에서도 성능 좋은 에이전트는 토큰 비용을 내고도 돈을 아낄 수 있었습니다.

하지만 소프트웨어를 만들고, 출시하고, 보안을 지키고, 유지보수하는 **전체 비용**이 업계 전반에서 줄었다는 근거는 아직 부족합니다. 저자는 지금까지의 연구가 많은 개발자의 체감과 대체로 일치한다며 글을 마쳤습니다.
