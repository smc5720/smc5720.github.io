## 개요

Dev.to 운영사 Forem의 공동 창업자 Ben Halpern은 [지난 글](https://dev.to/dailycontext/our-looping-factory-cut-dev-page-load-time-by-75-and-counting-1hnf)에서 성능 개선과 유지보수 작업을 [OpenHands](https://github.com/All-Hands-AI/OpenHands) 기반 자율 루프로 넘긴 경험을 소개했습니다. 한 달 동안 이 루프들이 올린 PR은 351개였고, Rails 평균 요청 시간은 70ms에서 16ms로 줄었습니다.

사람이 실행 루프에서 빠지자 다른 고민이 생겼습니다. 공장이 알아서 돌아가는데, 지금 무슨 일이 벌어지는지는 어떻게 확인할까요? 그는 AI 도구를 둘러싼 UI가 지나치게 획일적이라고 지적하고, 자기 시스템에 맞춘 관측용 대시보드를 직접 만들었습니다.

## 본문

### 채팅창은 계기판이 아니다

Halpern은 터미널, 프롬프트 입력창, 마크다운 로그 같은 텍스트 인터페이스가 앞으로도 중요하다고 봅니다. 언어 모델이 일하는 방식과도, 개발자가 즉흥적으로 의도를 전하는 방식과도 잘 맞기 때문입니다.

문제는 그 주변 UI가 하나같이 비슷하다는 점입니다. 역사상 가장 뛰어난 소프트웨어 생성 엔진을 손에 쥐고도, 이를 다루는 화면은 거의 다 다크 모드 채팅창에 깜빡이는 커서, 그리고 끝없이 올라가는 JSON 도구 호출 로그입니다. 그는 "채팅창은 대화하기엔 괜찮지만 계기판으로는 형편없고, 모든 플랫폼이 똑같이 생겼다"고 꼬집었습니다.

### 스크롤백으로는 상태를 알 수 없다

대화형 세션이 하나뿐이라면 머릿속으로 상황을 따라갈 수 있습니다. 어느 브랜치인지, 어떤 모델을 쓰는지, 테스트가 왜 깨졌는지 텍스트가 흘러가는 걸 직접 봤으니까요.

하지만 격리된 git worktree 위에서 루프 여덟 개가 10분마다 돌고, 최신 모델 구독 세 개를 번갈아 쓰고, 진행 중인 PR이 수십 개라면 얘기가 다릅니다. 채팅 기록만 뒤져서는 아래 같은 기본적인 운영 질문에도 답하기 어렵습니다.

- Rust 루프가 PR을 멈춘 이유가 후보가 바닥나서인지, `WIP <= 1` 제한이 꽉 차서인지, 오래된 `.gitconfig.lock` 파일이 worktree를 막아서인지
- Claude Opus 5.5가 레이트 리밋에 걸려 쿨다운에 들어갔는지, 라우터가 다음 실행을 Gemini 4 Argon이나 GPT-6.1 Sol로 제대로 넘겼는지
- PR `#24547`이 10분 주기 CI 점검에서 스스로 고쳐지고 있는지, 아니면 같은 테스트 실패로 수리를 세 번째 반복하고 있는지

이 그림을 맞추려고 대화 로그 다섯 개를 열거나 CLI 명령을 네 번 쳐야 한다면 사람은 다시 '고기 라우터(meat router)'가 됩니다. Halpern은 관측성의 핵심이 로그를 어딘가에 모아두는 데 있지 않고, 5초 안에 판단을 내릴 수 있게 데이터를 정리하는 데 있다고 말합니다.

### 도구로 계기판을 직접 만든다

그는 AI 도구의 인터페이스가 밋밋하다는 점이 오히려 아이러니하다고 봅니다. 지금 보고 있는 바로 그 도구로 더 나은 인터페이스를 손쉽게 만들 수 있기 때문입니다.

오후 한나절 만에 만든 대시보드가 1~2년 뒤 전문 AI 관측 제품을 따라잡으리라고 기대하지는 않는다고 했습니다. 자율 소프트웨어를 관리하는 시각적 문법은 아직 초기 단계이고, 언젠가는 전문 플랫폼이 이 문제를 풀 거라는 입장입니다.

다만 그때까지 기본값에 만족할 필요는 없다고 강조합니다. 자기 시스템의 조작 지점에 딱 맞춘 인터페이스가 범용 채팅 셸보다 낫고, AI 코딩 도구를 쓰면 시스템이 바뀌는 속도에 맞춰 인터페이스도 빠르게 고칠 수 있습니다. 그래서 그는 불평만 하지 않고 루프를 만들면서 맞춤형 관제 화면도 함께 만들었습니다.

### 자동화 관측소(Automation Observatory)

![observatory](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/dp75fjh83xov0nhewuvs.png)

Halpern은 OpenHands의 기본 테마와 홈 화면을 걷어내고 직접 만든 관측 플랫폼으로 바꿨습니다. 본인은 "최소한의 조치"라고 표현했지만, 도구를 개선하는 일도 유지보수의 일부라서 계속 다듬고 있다고 합니다. 이 화면은 **Schema v1 Canvas 확장으로 패키징해서, 코어 앱을 포크하지 않아도 업스트림 업그레이드 후에도 그대로 유지됩니다.**

화면의 각 영역은 공장을 조율하면서 실제로 내려야 했던 판단과 하나씩 연결됩니다.

**1. 자율 루프 레지스트리.** 최근 대화 목록 대신 화면 중앙에 Airtable 스타일 표를 두고 워크플로 아홉 개를 보여줍니다. `perf-loop`, `rust-loop`, `error-loop`, `test-loop`, `deps-loop`, `issue-loop`, `github-pr-reviewer`, `pr-merge-loop`, `worktree-pruner`입니다. 행마다 실시간 상태, 실행 주기, WIP 상한, 열린 PR 수가 나오고, 그 자리에서 일시정지·즉시 실행·특정 모델 고정을 할 수 있습니다.

**2. 모델 구독 잔량과 쿨다운.** 3열짜리 시트로 모델 라우터 상태를 추적합니다. 대상은 Gemini 4 Argon(`agy-acp`), Claude Opus 5.5(`claude-acp`), GPT-6.1 Sol(`codex-acp`)입니다. 모델별 실행 분포, 8시간 쿨다운 여부를 보여주고, 자격 증명이 갱신되면 한 번 클릭으로 초기화할 수 있습니다.

**3. 열린 PR 점검 레이더.** 자율 루프가 연 PR은 모두 `5 -> 10 -> 20 -> 40`분 지수 백오프 일정에 따라 CI 실패나 리뷰 코멘트를 점검합니다. 레이더에는 대기열의 PR마다 현재 백오프 단계, 시도한 수리 횟수, 다음 점검까지 남은 시간이 실시간으로 표시됩니다.

**4. 임시 worktree 관리.** 하단 표에서 격리된 `/data/worktrees/*` 체크아웃의 개수와 생성 시간, 읽기 전용 Postgres 상태, Mac 브리지 상태를 확인합니다. 병렬로 돈 `git gc`가 고아 디렉터리를 남겼을 때도 worktree 나이가 한 시간을 넘어가는 모습이 이 화면에 바로 드러났다고 합니다.

### 사람의 판단을 위한 설계

이 대시보드가 텍스트를 대신하지는 않습니다. 피드 랭킹 아이디어를 탐색하거나 4단계짜리 JavaScript 에셋 정리 작업을 함께 진행할 때는 지금도 "New Chat"을 누르거나 터미널을 엽니다.

달라진 점은 *대화*와 *감독*을 분리했다는 데 있습니다. Halpern은 좋은 인터페이스가 운영상의 잡음을 곁눈으로 볼 수 있을 만큼 압축해 준다고 설명합니다. 커피를 마시며 대시보드를 훑어보고, 루프 여덟 개가 모두 정상이고 `rust-loop`가 Argon에 고정된 채 PR 하나를 리뷰 중이라는 걸 확인한 뒤 탭을 닫으면 끝입니다.

그는 에이전트 시스템을 위한 인터페이스가 어떤 모습이어야 하는지 이제 겨우 탐색을 시작했을 뿐이라고 말합니다. 그리고 코드를 짜는 에이전트가 있으니, 누군가 조종석을 설계해 줄 때까지 기다릴 필요가 없다는 말로 글을 맺습니다.
