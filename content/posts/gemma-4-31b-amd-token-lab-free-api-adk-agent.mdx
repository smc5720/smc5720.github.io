## 개요

AMD AI 개발자 프로그램(AMD AI Developer Program)에 가입하면 **AMD Token Lab**이라는 무료 API를 쓸 수 있습니다. OpenAI 호환 API라서 기존 SDK를 그대로 붙일 수 있고, 카드 등록이나 크레딧 신청 절차도 없습니다. 키 하나를 받으면 30일 동안 10포인트 예산 안에서 쓸 수 있습니다.

작성자 xbill은 이 API로 Gemma 4 31B를 호출하는 로컬 채팅 페이지와 터미널 클라이언트, Google ADK(Agent Development Kit) 에이전트를 직접 만들었습니다. 글에 나온 수치는 모두 2026년 11월 13일에 실제로 보낸 요청에서 나온 값입니다. 요청 23건을 보내는 동안 쓴 포인트는 10포인트 중 0.000335였습니다.

코드는 GitHub 저장소 [gemma4-dev/tokenlab-sglang-amd-31b](https://github.com/xbill9/gemma4-dev/tree/main/tokenlab-sglang-amd-31b)에 있습니다.

## Token Lab은 어떤 서비스인가

Token Lab은 자신을 "AMD Instinct와 Radeon에서 서빙하는 주요 오픈 모델용" OpenAI 호환 API라고 소개합니다. 기본 URL은 `https://api.tokenlab.amd.com/v1`이고 curl, OpenAI·Anthropic SDK, LangChain, AMD AI Notebooks에서 호출할 수 있습니다.

AMD AI 개발자 프로그램의 클라우드 크레딧 페이지에는 선택지가 세 가지 있습니다. AMD Instinct Developer Cloud, Fireworks AI, 그리고 Token Lab입니다. 이 가운데 "크레딧 신청 불필요(No credit request needed)"라고 적힌 것은 Token Lab뿐입니다.

카탈로그에는 모델 10개가 올라와 있고 전부 무료입니다. Gemma 4 31B, DeepSeek V4 Flash와 V4.1 Flash, Qwen3.8 27B, MiniCPM 모델 3종, 의사결정(decision) 모델 3종입니다. Gemma-4-31B-IT는 텍스트와 이미지를 입력으로 받고, 컨텍스트 길이는 262,144토큰입니다.

새 키에 주어지는 사용량은 다음과 같습니다.

| 항목 | 값 |
| :--- | :--- |
| 포인트 | 이용 기간 동안 10포인트 |
| 이용 기간 | 30일, 15일 연장 1회 가능 |
| 속도 제한 | 키당 분당 20회 요청 |
| Gemma 4 31B 요율 | 입력 100만 토큰당 0.035포인트, 출력 100만 토큰당 0.07포인트 |
| 사용자 부담 비용 | 없음 |

Token Lab 설명에 따르면 포인트는 모델별 상대 사용량을 나타내는 단위이고, 큰 모델일수록 토큰당 포인트를 더 많이 씁니다.

## 가입부터 첫 호출까지

### 준비물

- AMD 계정용 이메일 주소
- `pip`이 설치된 Python 3
- 에이전트 실습용 `google-adk`, `litellm` (`pip install google-adk litellm`)
- `gemma4-dev` 저장소 클론, 또는 `tokenlab-sglang-amd-31b` 디렉터리만

### 1단계: AMD AI 개발자 프로그램 가입

프로그램 홈페이지에는 "가입은 무료이며, AMD 하드웨어에서 AI를 만들고 최적화하고 확장하도록 돕는다"고 적혀 있습니다.

https://developer.amd.com 에서 **Join the Program**을 누릅니다. AMD 계정이 없다면 가입 양식 작성, 이메일 인증, AI Academy 접속 순서로 진행합니다. 계정이 이미 있으면 로그인한 뒤 가입 양식만 열면 됩니다.

회원 혜택에는 DeepLearning.AI 1개월 멤버십, 행사 사전 등록, AMD 엔지니어가 참여하는 비공개 Discord, Radeon GPU나 Ryzen AI PC를 주는 월간 경품 추첨도 있습니다.

### 2단계: Token Lab 키 발급

https://notebooks.amd.com/tokenlab 에 접속해 **AMD AI Developer Program (Global) Login**으로 로그인합니다. 화면에 나오는 세 단계는 키 받기, 기본 URL 복사, 카탈로그 모델 호출입니다.

대시보드에서는 남은 포인트, 최근 30일 요청 수, 남은 일수, 속도 제한, 키 상태를 보여줍니다. 키를 재발급하거나 폐기하는 버튼도 있는데, 재발급해도 포인트와 이용 기간은 그대로 남습니다.

키는 본인만 읽을 수 있는 `.env` 파일에 넣고 커밋하지 않습니다.

```bash
cd tokenlab-sglang-amd-31b
umask 077; echo 'TOKENLAB_API_KEY=tl-...' > .env
```

기본 URL과 모델 이름은 커밋되는 `tpu.env`에 둡니다.

```bash
TOKENLAB_BASE_URL=https://api.tokenlab.amd.com/v1
MODEL_NAME=Gemma-4-31B-IT
```

### 3단계: 첫 호출

`make query`를 실행하면 채팅 완성 요청을 한 번 보내고 응답 원문을 출력합니다.

```json
{
  "model": "Gemma-4-31B-IT",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "The capital of Australia is Canberra."
      },
      "finish_reason": "stop",
      "matched_stop": 106
    }
  ],
  "usage": {
    "prompt_tokens": 20,
    "completion_tokens": 8,
    "cost": 1.1228e-06
  }
}
```

응답마다 포인트 단위의 `cost` 필드가 붙어 있어서, 클라이언트가 누적 사용량을 직접 계산할 수 있습니다.

### 엔드포인트 뒤에는 무엇이 있나

`make models`를 실행하면 Token Lab이 공개한 모델 카드를 볼 수 있습니다.

```json
{
  "id": "Gemma-4-31B-IT",
  "name": "Gemma 4 31B",
  "description": "Dynamic sglang-router service managed by Model Ops",
  "context_length": 262144,
  "supported_parameters": ["temperature", "max_tokens", "top_p", "stream",
    "response_format", "tools", "tool_choice", "reasoning_effort"],
  "architecture": {"input_modalities": ["text", "image"], "output_modalities": ["text"]}
}
```

모델 카드에 "sglang-router"라고 적혀 있고 응답에도 SGLang 고유의 `matched_stop` 필드가 들어 있으니, Gemma 4 31B는 SGLang 위에서 돌아갑니다. 같은 카탈로그의 MiniCPM 모델 3종은 "vllm-router" 서비스입니다. 하드웨어는 AMD Instinct와 Radeon이라고만 밝히고 있습니다.

지원 파라미터에 도구 호출(`tools`)과 JSON 출력(`response_format`)이 모두 들어 있어서, 뒤에 나올 에이전트를 만들 수 있습니다.

## Token Lab 위에 만든 세 가지 클라이언트

### 로컬 채팅 페이지

`chat_ui.py`는 같은 저장소의 TPU v5e vLLM 환경에서 쓰던 채팅 페이지를 Token Lab에 연결한 것입니다. 표준 라이브러리만 쓰는 Python 스크립트로, `127.0.0.1`에서 페이지 하나를 띄우고 `/v1/*` 요청에 키를 붙여 Token Lab으로 넘깁니다. 그래서 키가 브라우저로 넘어가지 않고 내 컴퓨터에만 남습니다.

```bash
$ make ui
Chat UI on http://localhost:8766 -> https://api.tokenlab.amd.com/v1 (Gemma-4-31B-IT)
```

![The local chat page answering through Token Lab, with the last reply's timings and points in the side panel](https://raw.githubusercontent.com/xbill9/gemma4-dev/main/docs/tokenlab-free/chat-page.6d02da62.jpg)

사이드 패널에서는 최대 토큰 수, temperature, top-p, 사고(thinking) 모드, 시스템 프롬프트를 조정할 수 있습니다. 마지막 응답의 첫 토큰 시간, 디코딩 속도, 토큰 수, 포인트와 모델 카드, 세션 누계도 함께 보여줍니다. 위 화면의 응답은 첫 토큰까지 4.96초, 디코딩 속도는 초당 9.5토큰, 사용 포인트는 0.00000942였습니다.

🖼 버튼으로 이미지를 첨부하면 OpenAI 이미지 형식의 data URL로 보냅니다. 사고 모드는 `chat_template_kwargs.enable_thinking`으로 Gemma의 추론 기능을 켜고, 추론 내용은 답변 위의 접히는 영역에 스트리밍됩니다.

### 터미널 클라이언트

`ask.py`는 저장소의 GTX 1650 Ti 환경용 `ask` 클라이언트와 같은 방식으로 동작합니다. 질문 하나만 던지고 끝내거나, 파이프로 입력을 넘기거나, 대화 기록을 유지하며 이어서 물어볼 수 있습니다.

```bash
$ make bin        # links ~/bin/ask-tokenlab
$ echo "Canberra is the capital of Australia." | ask-tokenlab translate to French
**Canberra est la capitale de l'Australie.**
```

파이프로 들어온 내용이 재료가 되고, 인자는 지시문이 됩니다. `-T`는 사고 모드, `-I photo.jpg`는 이미지 첨부, `-r`은 JSON 원문 출력입니다. 인자 없이 실행하면 대화 모드로 들어가고, `!`를 입력하면 기록을 지웁니다.

### ADK 에이전트

`tokenlab_agent/`는 Google ADK로 만든 작은 에이전트입니다. ADK는 LiteLLM의 OpenAI 프로바이더로 Token Lab에 접속하기 때문에, 연결 설정은 모델 객체 하나로 끝납니다.

```python
model = LiteLlm(
    model="openai/Gemma-4-31B-IT",
    api_base="https://api.tokenlab.amd.com/v1",
    api_key=TOKENLAB_API_KEY,
    num_retries=30,
    timeout=600,
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)
```

에이전트에는 도구가 두 개 있습니다. `list_tokenlab_models`는 Token Lab이 지금 서빙 중인 모델 목록을 돌려줍니다. `count_and_range`는 개수 세기, 필터링, 최솟값·최댓값 계산을 코드로 처리합니다. 그래서 모델이 정확한 수치를 인용하고, 어떤 필터를 썼는지도 밝히게 됩니다.

```python
def count_and_range(numbers: list[float], at_least: Optional[float] = None,
                    below: Optional[float] = None) -> dict:
    """Count the numbers that satisfy at_least <= x < below, and give their min, max and sum."""
```

`run_agent.py`는 한 턴을 실행하고 도구 호출마다 경과 시간을 함께 출력합니다.

```bash
$ python3 run_agent.py
   8.1s call   count_and_range({"at_least": 10, "numbers": [0, 2, 3, 20, 21, 22, 23, 10, 11, 12, 13]})
   8.1s result {"filter": "10 <= x", "total_values": 11, "count": 8, "min": 10, "max": 23, "sum": 132}
  12.3s answer There are 8 values that are 10 or more, using the filter "10 <= x".
```

Gemma는 "10 이상"을 `at_least: 10`으로 해석했고, 도구가 8을 돌려주자 답변에서 그 개수와 필터를 그대로 인용했습니다. 두 번째 도구를 쓰는 예시도 있습니다.

```bash
$ python3 run_agent.py "Which models on Token Lab are served by vLLM, and which by SGLang? Short list."
  25.7s call   list_tokenlab_models({})
  38.4s result {"models": [{"id": "Clef", "service": "Dynamic aux-router service managed by Model Ops", ...
  48.9s answer **vLLM:**
* MiniCPM5-2B
* MiniCPM-V-4.7-1B
* MiniCPM-V-4.7-35B-A3B
**SGLang:**
* DeepSeek-V4.1-Flash
* DeepSeek-V4-Flash
* Gemma-4-31B-IT
* Qwen3.8-27B
```

같은 에이전트를 ADK 기본 도구로도 실행할 수 있습니다. `make agent`는 터미널에서 `adk run`을, `make agent-web`은 8767번 포트에서 `adk web`을 띄웁니다.

## 무료 API는 얼마나 빠른가

노트북에서 temperature 0으로 스트리밍 요청을 한 번에 하나씩 보내 측정한 결과입니다.

| 사고 모드 | 생성 토큰 | 첫 토큰 | 전체 시간 | 디코딩 속도 |
| :--- | :--- | :--- | :--- | :--- |
| 끔 | 97 | 5.04초 | 17.8초 | 7.55 tok/s |
| 끔 | 256 | 1.22초 | 35.0초 | 7.55 tok/s |
| 끔 | 35 | 2.23초 | 12.3초 | 3.41 tok/s |
| 켬 | 390 (추론 291) | 3.35초 | 199.8초 | 1.98 tok/s |

하루 동안 단일 요청의 디코딩 속도는 초당 2.0~9.5토큰 사이를 오갔고, 첫 토큰은 1.2~5.0초 뒤에 도착했습니다. 측정한 요청에서는 응답 헤더가 0.5초 안에 왔고, 첫 토큰이 나오기 전까지 스트림에 keep-alive 핑이 이어졌습니다.

이 엔드포인트는 Token Lab 사용자 전원이 함께 씁니다. Gemma 4 31B는 전체 사용자를 합쳐 동시 요청 128건까지 받고, 이를 넘으면 `Retry-After: 1` 헤더와 함께 HTTP 429를 돌려줍니다. 위 수치는 그날의 Token Lab 부하를 보여줄 뿐, 뒤에 있는 GPU 성능을 말해주지는 않는다고 작성자는 덧붙였습니다.

### 팁: 스트림이 시작되기 전에 재시도하기

Token Lab은 모델이 공유 한도에 걸렸거나 키가 분당 20회를 넘으면 429를, 백엔드가 재시작 중이면 502·503·504를 돌려줍니다. FAQ에서는 몇 초 기다렸다가 `Retry-After`에 맞춰 다시 보내라고 안내합니다.

채팅 페이지와 터미널 클라이언트는 `tokenlab.py`가 응답이 시작되기 전에 이 재시도를 처리하고, 에이전트는 LiteLLM의 `num_retries`로 같은 효과를 얻습니다. 다만 스트림이 시작된 뒤 끊기면 재시도할 상태 코드가 없습니다. 정상적인 스트림은 `data: [DONE]`으로 끝나기 때문에, 채팅 페이지는 이 줄 없이 끝난 응답을 따로 표시합니다.

스트림에는 엄격한 파서가 걸려 넘어질 만한 줄도 섞여 있습니다. 대기 중에는 `: ping`, 이벤트마다 `id: N`, `[DONE]` 직전에는 `event: done`이 옵니다. `data:`로 시작하는 줄만 읽으면 됩니다.

## 세 가지 크레딧 옵션 비교

프로그램 클라우드 크레딧 페이지에 있는 세 선택지를 비교하면 다음과 같습니다.

| | Token Lab | AMD Instinct Developer Cloud | Fireworks AI |
| :--- | :--- | :--- | :--- |
| 제공 형태 | 모델 카탈로그 API | AMD Instinct GPU 자체 | 관리형 모델 엔드포인트 |
| 크레딧 신청 | 🥇 불필요 | 양식 제출 후 검증 | 양식 제출 후 검증 |
| 설정 | 🥇 키 하나 | 직접 스택 구성 (vLLM, SGLang, PyTorch) | 🥈 키 하나 |
| 모델 선택 자유도 | 카탈로그 한정 | 🥇 배포하는 건 무엇이든 | 카탈로그 |
| 속도 | 공유, 변동 있음 | 🥇 GPU 단독 사용 | 관리형 |
| 만료 | 활성화 후 30일 | 활성화 후 30일 | 발급 후 90일 이내 |

작성자는 Token Lab부터 시작하라고 권합니다. 비용도 신청 절차도 없고, 키 말고는 준비할 게 없기 때문입니다. Gemma 4 31B를 카탈로그의 다른 모델과 비교해 보거나 프로토타입을 만들고 에이전트를 연결해 보기에 적합하다는 설명입니다.

프로토타입에 안정적인 속도가 필요하거나, 카탈로그에 없는 모델을 쓰고 싶거나, 전용 서버가 필요해지면 AMD Instinct Developer Cloud 크레딧을 신청해 직접 서빙하면 됩니다. 같은 저장소의 `gpu-vllm-mi300x-31b`에 같은 모델을 vLLM으로 서빙하는 구성이 있습니다.

## 정리

작성자가 확인한 내용을 요약하면 다음과 같습니다.

- 🟢 프로그램 가입은 무료이고, Token Lab은 크레딧 신청이 필요 없습니다. 키 하나에 10포인트, 30일, 분당 20회 요청이 주어집니다.
- 🟢 Gemma 4 31B는 OpenAI API 형식으로 텍스트와 이미지를 처리하고, 사고 모드와 도구 호출, 262,144토큰 컨텍스트를 지원합니다.
- 🟢 글에 나온 작업 전체(요청 23건)에 10포인트 중 0.000335를 썼습니다.
- 🟢 로컬 채팅 페이지는 키를 내 컴퓨터에만 두고, 응답마다 시간과 포인트를 보여줍니다.
- 🟢 ADK 에이전트는 `LiteLlm` 객체 하나로 Token Lab에 연결되고, 도구가 계산한 정확한 결과로 개수 질문에 답했습니다.
- ⚠️ 공유 엔드포인트라서 단일 요청 디코딩 속도가 초당 2.0~9.5토큰으로 들쭉날쭉했고, 첫 토큰까지 최대 5초가 걸렸습니다.
- ⚠️ Token Lab 뒤의 Gemma 4 31B는 SGLang으로 돌아가며, GPU 모델은 공개하지 않았습니다.
- ❌ 공유 한도 128건을 넘으면 429가 나와 다시 보내야 하고, 응답 도중 끊긴 스트림은 자동으로 재시도할 수 없습니다.

측정 범위는 2026년 11월 13일 노트북 한 대에서 `api.tokenlab.amd.com`으로 요청을 하나씩 보낸 결과이며, 속도 표는 Gemma-4-31B-IT에 temperature 0 조건입니다. 시간에는 네트워크 지연과 다른 사용자의 부하가 포함돼 있어 시간대마다 달라집니다. 동시 요청, 긴 프롬프트, 답변 정확도는 측정하지 않았습니다. 에이전트는 google-adk 2.13.0과 litellm 1.106.4로 실행했습니다.
