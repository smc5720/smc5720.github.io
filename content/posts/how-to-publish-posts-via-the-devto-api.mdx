## 개요

dev.to에 글을 올릴 때마다 에디터에 본문을 붙여넣고, 태그를 달고, 서식을 다시 손보는 일을 반복하고 있다면 API로 이 과정을 자동화할 수 있습니다. 작성자 Julie는 dev.to API를 쓰는 방법 두 가지를 소개합니다.

첫 번째는 `curl` 명령입니다. API가 어떤 요청을 기대하는지 그대로 볼 수 있습니다. 두 번째는 같은 요청을 대신 보내 주는 Python 스크립트입니다. 여기에 많은 사람이 헷갈려하는 이미지 처리 방법도 함께 다룹니다.

## 본문

### 먼저 API 키부터 발급받기

dev.to 계정에서 **Settings → Extensions → DEV Community API Keys**로 들어갑니다. 키 이름을 적고 **Generate API Key**를 누르면 됩니다.

버튼 아래 **Active API Keys** 목록을 펼치고, 방금 만든 키 옆 화살표를 누르면 키 값이 보입니다.

작성자는 키를 소스 코드에 직접 붙여넣지 말라고 강조합니다. Python 예제에서는 환경 변수에서 키를 읽어 옵니다.

### 방법 1: curl로 요청 구조 확인하기

처음에는 간단한 예제로 실제 HTTP 요청이 어떻게 생겼는지 보는 편이 좋습니다. 터미널을 열고(Windows라면 `Git Bash`를 써도 됩니다) 아래 명령에서 `YOUR_KEY`만 본인 키로 바꿔 실행합니다.

```bash
curl -X POST https://dev.to/api/articles \
  -H "api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "article": {
      "title": "My First Post",
      "body_markdown": "# Hello\n\nThis is my post.",
      "tags": ["python", "api"],
      "published": false      
    }
  }'
```

각 부분의 역할은 이렇습니다.

- `curl -X POST`: 새 글을 만들라는 요청입니다.
- `-H`: 헤더를 붙입니다. 하나에는 `api-key`를 담고, 다른 하나에는 본문이 JSON이라고 알립니다.
- `-d`: JSON 형식의 요청 본문입니다.

> `published`의 기본값은 `false`입니다. 이 상태로 보내면 글은 초안으로 저장되고 **Dashboard**에서 확인할 수 있습니다. 서식을 확인하고 고친 다음 원할 때 발행하면 됩니다. `true`로 바꾸면 바로 공개됩니다.

다만 이 방식에도 단점이 있습니다. API 키, 제목, 태그, 본문을 매번 터미널에 직접 입력하거나 붙여넣어야 합니다. 원래 없애려던 반복 작업이 그대로 남는 셈이라, 작성자는 이 과정을 스크립트에 맡기자고 제안합니다.

### 방법 2(권장): Python 스크립트로 자동화하기

Markdown으로 글을 쓴다면 파일 맨 위에 이미 front matter가 있을 가능성이 높고, 그 정보를 그대로 쓸 수 있습니다. front matter를 처음 쓴다면 아래처럼 몇 줄만 추가하면 됩니다.

```markdown
---
title: My First Post
tags: [python, api]
---
```

주의할 점이 두 가지 있습니다. 콜론 뒤에는 반드시 공백을 넣어야 합니다. `title:My First Post`처럼 붙여 쓰면 YAML이 읽지 못합니다. 그리고 dev.to는 글 하나에 **태그를 최대 4개**까지만 받습니다.

필요한 패키지는 두 개입니다. API 요청에 쓸 `requests`, 글에서 front matter를 읽어 올 `python-frontmatter`입니다.

```bash
pip install requests python-frontmatter
```

아래 코드를 Python 파일로 저장하고 `frontmatter.load()`에 올릴 글의 경로를 넣습니다. API 키는 환경 변수로 설정합니다. Git Bash에서는 `export DEVTO_API_KEY="your_key"`, PowerShell에서는 `$env:DEVTO_API_KEY="your_key"`입니다.

```python
import os

import frontmatter
import requests

URL = "https://dev.to/api/articles"
API_KEY = os.environ["DEVTO_API_KEY"]

post = frontmatter.load("posts/my-post.md")

article = {
    "article": {
        "title": post["title"],
        "body_markdown": post.content,
        "tags": post.get("tags", []),
        # Optional: if the same post also lives on your own blog
        # "canonical_url": "https://your-blog.example.com/my-post",
        "published": False
    }
}

response = requests.post(
    URL,
    json=article,
    headers={"api-key": API_KEY, "Content-Type": "application/json"}
)

if response.status_code == 201:
    print("Draft Created:", response.json()["url"])
else:
    print("Failed:", response.status_code, response.text)
```

`requests.post()`를 앞의 curl 명령과 나란히 놓고 보면 보내는 내용은 똑같습니다. **URL, 헤더, JSON 본문** 세 가지입니다. 둘 다 평범한 HTTP 요청이고, 스크립트는 그 요청을 매번 손으로 쓰지 않게 해 줄 뿐입니다.

### 이미지는 공개 URL로

Markdown에서 `./imgs/screenshot.png` 같은 로컬 경로로 이미지를 넣었다면 dev.to에서는 이미지가 깨집니다. dev.to는 내 컴퓨터 디스크에 접근할 수 없으니, 이대로라면 이미지를 하나씩 직접 올려야 합니다.

해결 방법은 누구나 접근할 수 있는 이미지 URL을 쓰는 것입니다. 개인 블로그, GitHub, 그 밖의 이미지 호스팅 서비스 어디든 괜찮습니다. API로 글을 올리면 dev.to가 각 이미지를 가져와 자체 사본을 저장하기 때문에, 원래 블로그에서 보이던 모습 그대로 dev.to에서도 보입니다.

> URL은 반드시 공개 상태여야 합니다. 로그인이 필요한 곳이나 사설 네트워크 안에 있는 이미지는 불러오지 못합니다.

### 정리와 팁

작성자는 API로 발행하면 5분짜리 복사·붙여넣기 작업이 명령 한 줄로 줄어든다고 말합니다. 덧붙인 팁은 세 가지입니다.

- 같은 글을 개인 블로그에도 올린다면 `canonical_url`을 지정해 검색 엔진에 원래 게시 위치를 알려 줍니다.
- 전체 파라미터는 [API 문서](https://developers.forem.com/api/v1#tag/articles/operation/createArticle)에서 확인할 수 있습니다.
- API 키는 환경 변수에 두고, 공개 저장소에는 절대 커밋하지 않습니다.
