## 개요

새 탭을 열 때마다 DEV(dev.to) 커뮤니티의 최신 글이 바로 뜨는 브라우저 확장 프로그램이 나왔습니다. 개발자 Jessica Doering이 만든 **DEV Tab**입니다. 무료이고 소스 코드도 공개되어 있습니다.

새 탭에서 개발 콘텐츠 피드를 보여 주는 daily.dev를 써 온 작성자는 "이걸 DEV 전용으로 만들면 어떨까" 하는 생각에서 개발을 시작했다고 밝혔습니다. 지금은 Chrome 웹 스토어와 Firefox 부가 기능 사이트 양쪽에서 설치할 수 있습니다.

- [Chrome 웹 스토어에서 설치 →](https://chromewebstore.google.com/detail/dev-tab/mfhbilfjgklgebkclbkabohhkibomnop)
- [Firefox 부가 기능에서 설치 →](https://addons.mozilla.org/en-US/firefox/addon/dev-tab/)

## 무엇을 할 수 있나

### 피드를 보는 방식이 다양하다

처음 구상은 단순했습니다. 새 탭을 열고, DEV에 올라온 글을 훑어보고, 관심 가는 글을 클릭하는 정도였습니다. 그런데 만들다 보니 기능이 계속 늘었다고 합니다.

![DEV Tab showing a grid of DEV posts](https://raw.githubusercontent.com/pinkpixel-dev/DEV-tab/main/screenshots/screenshot.png)

글 목록은 Today, This Week, Rising, Latest 탭으로 나눠 볼 수 있습니다. 트렌드, 이벤트, 팟캐스트, 영상은 별도 섹션에 모았습니다.

태그 필터로 관심 주제 사이를 빠르게 오갈 수 있습니다. 자주 보는 태그는 저장하고, 보고 싶지 않은 태그는 숨기고, 특정 DEV 조직(organization)의 글만 따로 팔로우할 수도 있습니다.

이 밖에도 이런 기능이 들어갔습니다.

- 새 탭 화면에서 바로 검색
- 방향키와 Enter 키로 이동하는 키보드 내비게이션
- 이미지를 줄이고 글을 더 많이 보여 주는 컴팩트 보기
- 반응 수와 최신 댓글 3개 미리보기
- 새 DEV 글 작성 바로가기
- 피드 캐싱(새 탭을 열 때마다 전부 다시 불러오지 않음)

작성자는 "특별히 혁신적인 건 없다"면서, 일부러 찾아다니지 않아도 DEV를 편하게 둘러볼 방법을 원했을 뿐이라고 설명했습니다.

### 계획에 없던 개인 대시보드

대시보드는 처음 계획에 없던 기능입니다. DEV에 글을 꽤 많이 쓰다 보니 자기 활동을 한눈에 보고 싶어졌다고 합니다.

확장 설정에 DEV API 키를 넣으면 개인 대시보드를 비롯한 추가 기능이 열립니다.

![DEV Tab dashboard with example statistics, charts, and post activity](https://raw.githubusercontent.com/pinkpixel-dev/DEV-tab/main/screenshots/dashboard.png)

대시보드에서는 팔로워 수, 조회수, 반응, 댓글, 신규 팔로워를 최근 7일·30일·90일 단위로 볼 수 있습니다. 일별 조회수 차트와 지난 연도까지 거슬러 볼 수 있는 활동 히트맵, 발행한 글과 임시 저장 글 목록도 있습니다. 최근 팔로워, 가장 많이 응원해 준 사용자, 독자 유입 경로도 확인할 수 있습니다.

작성자가 특히 마음에 들어 하는 부분은 활동 히트맵과 글별 통계를 함께 보는 화면입니다. 언제 활발하게 활동했는지, 글마다 반응이 어땠는지 돌아보는 재미가 있다고 합니다. 위 스크린샷의 수치는 예시용 가짜 데이터입니다.

## 계정 연결은 선택 사항

DEV Tab은 계정이나 API 키 없이도 쓸 수 있습니다. 공개 피드, 검색, 필터 같은 둘러보기 기능은 모두 그대로 동작합니다.

DEV 계정을 연결하면 기능이 몇 가지 더 생깁니다. 팔로우한 태그 기준의 개인 피드, 읽기 목록(reading list), 시맨틱 검색입니다. API 키는 [DEV 설정 페이지](https://dev.to/settings/extensions)에서 발급받을 수 있습니다.

확장에는 백엔드도, 분석 도구도, 추적 기능도 없습니다. API 키는 브라우저의 로컬 확장 저장소에만 저장되고, 인증이 필요한 API 요청을 보낼 때만 DEV로 전송됩니다. DEV가 이미 공개하는 정보를 보여 주자고 별도 서비스를 하나 더 두고 싶지는 않았다는 게 작성자의 설명입니다.

## 아쉬운 점: API가 허용하지 않는 기능

DEV API의 제약 때문에 넣지 못한 기능도 있습니다. 확장 안에서 글에 반응을 남기거나, 댓글을 달거나, 읽기 목록에 저장할 수는 없습니다.

반응 수와 댓글 미리보기는 볼 수 있지만, 실제로 글과 상호작용하려면 DEV 사이트에서 해당 글을 열어야 합니다. 작성자는 언젠가 이런 동작을 피드 안에서 바로 처리하고 싶지만, 지금은 API가 지원하는 범위가 거기까지라고 밝혔습니다.

## 기술 스택: WXT, React, TypeScript

확장 프레임워크로는 [WXT](https://wxt.dev/)를 썼고, React와 TypeScript를 함께 사용했습니다. 작성자는 WXT를 이번에 처음 써 봤는데, 코드베이스 하나로 Chrome과 Firefox 버전을 모두 빌드할 수 있다는 점이 특히 좋았다고 합니다.

공을 들인 부분은 새 탭을 열 때마다 피드를 통째로 다시 불러오지 않게 만드는 일이었습니다. 각 피드의 첫 페이지를 10분 동안 캐시해 두고, 오프라인 상태에서도 이전에 불러온 글은 보이도록 했습니다. 새 탭은 하루에도 수없이 여는 화면이라, 작은 차이도 크게 느껴진다고 봤기 때문입니다.
